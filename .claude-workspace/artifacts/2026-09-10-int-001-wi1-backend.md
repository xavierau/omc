## Key Decisions

- **`00`-prefixed IDD numbers need a fallback, not just `defaultCountry`.** `libphonenumber-js`'s HK metadata registers IDD prefixes `001/002/003/005/006/007/009`, not plain `00` — `parsePhoneNumberFromString('0085298765432', 'HK')` silently mis-parses to a bogus Mexico-calling-code number instead of failing closed. `e164-parser.ts` retries with a `00→+` substitution when the direct parse is invalid and the input starts with `00`, which is what actually gets `0085298765432` (the threat model's own required test fixture) to `+85298765432`.
- **Zero-width Unicode must be rejected by a pre-filter, not delegated to the library.** `parsePhoneNumberFromString('+852​98765432', 'HK')` returns a *valid* parse — the library silently discards the zero-width space as if it were formatting. `e164-parser.ts` runs `/^[+\d\s().-]+$/` before ever calling the library, so this class of input is rejected structurally rather than by hoping the library's leniency happens to align with our threat model.
- **`decidePartnerConsentAction` takes only the latest status, not the full row/history.** The plan's Tests(first) bullet names an "opted_out-then-opted_in latest" case; since only the LATEST row decides (OD-14's restated invariant), that case collapses to the ordinary `opted_in → noop` branch for this pure function — the history itself only matters at the DB/trigger layer, which is exercised separately (scratch-DB Assertion C, and the migration 072 trigger scoping to `source='partner_api'`).
- **`createOrGetMember` omits `externalRef` from its input**, despite the plan's illustrative signature block listing it. The seam's own prose description ("calls insertMember... After a created outcome it publishes member.created") never assigns it a job, and `integration_member_refs` upsert is explicitly itemized as the JOB PROCESSOR's own step 4, separate from the `createOrGetMember` call in step 2. Accepting-and-ignoring a parameter is worse than WI-3 adding it to the call site once it actually implements ref-linking. **Flagged for WI-3's reviewer** — if WI-3's design actually wants the seam itself to write the ref, that's a small, obvious addition, not a redesign.
- **`createOrGetMember`'s publisher dependency defaults to a no-op**, exactly matching the plan's own statement that WI-6 will "wire the real publisher via factory" by modifying `create-or-get-member.ts`. The seam is fully functional and fully tested today without a hard import of infrastructure that doesn't exist until WI-6; WI-6's expected diff here is a single default-value swap, nothing else.
- **`ip-range.ts`, `webhook-signature.ts`, `delivery-outcome.ts` are implemented now**, even though nothing calls them yet (WI-2/5/6 are their real callers), because the plan explicitly assigns these files to WI-1 and their formats are fully specified in the plan/threat text (the exact CIDR blocklist, the exact signature base strings, the exact classify-outcome rule) — implementing them now avoids a file-ownership collision when WI-2/5/6 land, and each has its own test coverage so it isn't unverified speculative code.
- **`loopback-test-guard.ts` was deliberately NOT created.** It's listed in WI-1's file list, but its shape is entirely dependent on `ssrf-guard.ts`'s interface, which WI-5 designs. Guessing at that interface now risks handing WI-5 a stub they have to understand and likely discard rather than saving them work. **Flagged for WI-5**: create `src/test-utils/loopback-test-guard.ts` once `ssrf-guard.ts` exists.
- **BigInt literal syntax (`0n`) is unavailable at this project's `ES2017` tsconfig target** (`tsc` error TS2737). `ip-range.ts`'s IPv6 masking uses `BigInt(0)`-style function calls throughout instead of literals — functionally identical, no tsconfig change (which would be out of WI-1's scope).
- **`integration-settings-repository.ts`'s entity read path excludes `outbound_secret_enc` at the SQL `.select()` column list**, not merely at the mapper level (T-H1) — a query-shape bug can't leak the ciphertext over the wire even before mapping. Verified by a test asserting the exact selected-columns string never contains `outbound_secret_enc`.
- **`INT001_SECRET_KEY` is not yet in `.env.example`** — that file is explicitly owned by WI-11 per the plan (single consolidated edit to avoid every WI touching it). Local dev/tests need `INT001_SECRET_KEY` set to a 32-byte base64 or hex string; secret-box tests set it themselves via `process.env` per-test.
