## Key Decisions

- **No slot logic re-implemented.** Every check goes through `bookingRulesAt(now, config)` + `parseBookingSubmission`; times through `slotsFor`; alternatives through `suggestTimes`; text through `summarize`. W1 files untouched.
- **AI terms timing:** the propose parse sets `termsRequired: false` (terms are read back, not yet accepted); create/confirm re-parse with `acceptTerms: true` and the full rules. The proposal stores the terms text it read back; if the current snapshot differs at create/confirm (changed, added or removed) the tool answers `terms_changed` and books nothing, so the stored text is always the one the diner heard (spec AC-10 "exact text").
- **`propose_booking_change` also returns `terms` and stores acceptance on the change request.** The brief names propose_booking only for the read-back; without it the change row would store an acceptance of text never read back.
- **Refusal envelope kept:** the AI tools keep `{error: 'invalid', fields, …}` (existing tests and the model's known shape) and add `suggestedTimes` plus a sentence in `note` only when the hours refused the slot; non-hours errors and hours-null output are byte-identical to before. The brief's `{ok:false, errors, suggestedTimes}` is read as content, not keys.
- **Suggestions on create/confirm re-checks too** (slot left the rules while the diner answered): same helper, no extra cost.
- **too_far suggestions:** W1 `suggestTimes` returns nothing past the window, so `suggestionsForRefusal` starts at the window's last date (nearest to the ask), falling back to today when that date has no slot.
- **Rate limit:** `/availability` uses the POST's limiter and key (`book003:agent:<ip>`, 10/min, Retry-After 60), so a run of availability reads counts toward the same per-IP budget (threat R2 "same rate limiter"). Separate keys would be friendlier to chatty agents; one-line change if wanted.
- **`/availability` 404 gate** = `resolveAgentBookingTenant` (as `/openapi.json`); it does not also 404 on a missing WhatsApp number (POST does, via its context step).
- **`/availability` query:** `from` and `days` required; `from` before HK today → `past`; `party_size` only validated (no live capacity; BOOK-010 later). Codes: `required`, `invalid`, `past`, `too_small`, `too_large`.
- **`open`** = at least one bookable time left (closed day, special closure, all inside notice, past the window → false).
- **Terms in `/availability`:** `{'zh-HK', en}` strings ('' = not set in that language), null when no terms.
- **Confirm reply terms source:** the row's `termsText` (exact accepted text), else the current snapshot; both null → today's text exactly.
- **Table time** appears through `summarize` ("Tables are for 2 hours." / "每枱用餐時間 2 小時。"), not repeated.
