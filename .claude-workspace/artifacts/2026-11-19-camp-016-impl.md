## Key Decisions

1. **One filter, three functions.** `campaign_audience_rated` computes audience, `is_lapsed`, `rating` and `included`; `_members` and `_counts` only select from it. The form count, the Settings bar and the send all call it, so they cannot drift.
2. **Classification parity.** The rate is `float8` division compared with `>=`, the same IEEE double JS uses, so the 0.9 / 0.6 boundaries agree with `classifyContactQuality` (DB test asserts six members, both boundaries). Thresholds and window are parameters from `contact-quality.ts`; a test runs with `p_green 0.95` to prove they are not constants. `classifyContactQuality` is unchanged.
3. **Selected audiences.** The form has no campaign yet, so the count passes `p_member_ids` (in the RPC POST body, never a URL); the send uses the saved `campaign_members` via `p_campaign_id`. DB test: both give the same set.
4. **Pre-086 campaigns keep their behaviour.** Snapshot `off`/NULL means no filter, except a win-back to all members with no snapshot, which keeps its old read: `schedule.inactiveDays` (default 30) and never-visited members excluded (`p_never_visited_lapsed = false`). Every win-back created since 086 stores its lapsed days, so this rule only reaches old rows.
5. **Win-back always has a lapsed filter.** The server fills the tenant default if the body omits it; the form locks the toggle on for win-back with a hint. Welcome campaigns store no filters (sent on join).
6. **Form skip level = the Settings level** (the design has only a toggle + "Default from Settings · Change"). An edit keeps the campaign's own snapshot.
7. **Non-admins** see the Campaigns group read-only (controls disabled, no Save, thresholds without the chevron) and no Bookings & AI agent group; `/dashboard/setup/bookings` is 404 for them.
8. **Desktop `/dashboard/setup`** moves to `profile` client-side (`matchMedia`), phone keeps the index: the server cannot know the viewport.
