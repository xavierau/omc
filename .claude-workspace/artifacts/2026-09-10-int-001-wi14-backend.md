## Key Decisions

**I-4 deviation — logged, not rejected.** The dispatch brief said "wire it so a
replayed nonce is rejected (401) and tested." I did not implement that. The partner
doc (`docs/integrations/member-api.md` §2, shipped before this dispatch) explicitly
promises: *"a repeat [nonce] within 10 minutes is treated as a retried, not a new,
request."* POST is content-addressed (T-H3b), so a replay legitimately reproduces the
same `job_id`/202 today; GET is read-only. Rejecting with 401 would (a) break that
already-published, partner-facing contract — a legitimate retry after a timeout would
now fail where it used to succeed — and (b) violate this dispatch's own Boundaries
("no API contract changes visible to partners"). I implemented the reviewer's other
named option instead: the signal is now *consumed* (a structured `console.warn` in
both routes) rather than silently dropped, closing the "dead signal, wasted Redis
call" complaint without the breaking change. **This needs an explicit decision from
whoever owns the partner contract** — if 401-on-replay is actually wanted, the doc
needs updating first (and partners notified), not the other way round.

**I-7 formula — corrected mid-implementation.** My first draft of the ON CONFLICT
formula ("adopt origin on null, keep origin on null, agree on match, else null") is
NOT the same as the review's `IS NOT DISTINCT FROM` formula, and I verified via a
5-line Python simulation that my first draft does **not** fix the reported bug — it's
mathematically identical to the old `COALESCE(existing, incoming)` for the exact
attributed-vs-unattributed collision the finding describes. Migration `074` uses the
review's exact strict-equality formula, verified against the attack scenario on a
scratch DB (Assertions L/M/N) before considering this done.

**I-8 — `updateOutboundBreakerState` split, not replaced.** It still handles the two
ABSOLUTE writes (reset-to-0 on a delivered success; resume's
streak-reset-to-0-and-active). Only the INCREMENT (the one actually racy path under
concurrency) moved to the atomic RPC.
