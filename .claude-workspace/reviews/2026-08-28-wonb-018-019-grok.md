# Code Review (Grok CLI): WONB-018/019 — RFC 4180 CSV parser + import template (#148 + #147)

## Summary

The RFC 4180 tokeniser, column-count rejection policy, upload-step wiring, template round-trip, and
dual-locale keys all land as specified: quoted commas no longer shift columns, rejected rows cannot be
posted, and #147's template/help is reachable on the existing csv step. One important gap remains — an
unterminated quote on the header line is swallowed and shown as `csv.errors.empty` instead of the
rejections panel. No wire/server/preview/commit leakage in `src`.

## 🔴 Critical (Must Fix)

None.

## 🟡 Important (Should Fix)

**`src/components/dashboard/import-wizard/parse-csv.ts:68`** — `parseCsv` never inspects
`records[0].unterminated`. An unclosed quote on the header line (e.g.
`phone,name,preferred_language,"tags` plus the rest of the file) makes the tokeniser emit one
unterminated record; `matchHeader` still succeeds, `slice(1)` is empty, and `classifyParseResult` maps
`phoneHeaderFound && rows=[] && rejected=[]` to `csv.errors.empty`. The operator sees "CSV is empty or
missing the phone column" instead of the rejections panel with `unterminated_quote` — the same
feedback-state hole the review's check C forbids for data rows.
- **Risk**: nothing is imported mangled (Next stays disabled), but a quote error is misdiagnosed as an
  empty file and the line/reason panel never appears. Easy to miss when the header's last field is the
  one left open.
- **Fix**: after a successful header match, if `records[0].unterminated`, return that record as a
  `CsvParseReject` (reason `unterminated_quote`) with `rows: []` so `classifyParseResult` takes the
  ok+panel path. Add a `parse-csv` fixture: quoted header that swallows following data lines →
  `rejected[0].reason === 'unterminated_quote'` and `csv.errors.empty` is not shown.
